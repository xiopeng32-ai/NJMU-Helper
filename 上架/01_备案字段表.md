### 导出签名公钥与 MD5

在签名 `.p12` 所在机器执行（替换文件名与别名）：

```bash
# 1. 看指纹：找 MD5 与 SHA-256
keytool -list -v -keystore release.p12 -storetype PKCS12 -alias 【别名】

# 2. 导出证书
keytool -exportcert -rfc -alias 【别名】 -keystore release.p12 -storetype PKCS12 -file cert.cer

# 3. 取公钥（备案系统要求的是这一串 Base64）
openssl x509 -in cert.cer -pubkey -noout
```

> 若手上只有 AGC 下载的 `.cer`，从第 2 步的 `openssl x509 -in xxx.cer -pubkey -noout` 开始。  
> 公钥是 `-----BEGIN PUBLIC KEY-----` 到 `-----END PUBLIC KEY-----` 之间的内容，不含首尾行。

## 四、填写前必须先统一的版本号

| 位置                               | 当前值                                         | 问题            |
| -------------------------------- | ------------------------------------------- | ------------- |
| `AppScope/app.json5`             | `versionName 1.9.9` / `versionCode 1009009` | 源码版本          |
| `entry/.../AboutPage.ets` 第 64 行 | `1.9.4`                                     | 关于页硬编码，与源码不一致 |
| 站内 hap / 网站文案                    | `2.0.3`                                     | 商店与站点对外版本     |

**建议**：确定一个对外版本（例如 2.0.3），把 `app.json5` 的 `versionName`、`versionCode`、`AboutPage.ets` 的 `currentVersion` 三处改一致，重新构建发布包，再用这个包去备案与上架。否则 AGC 审核会问「包内版本与商店信息不符」。

> 我没有直接改：改版本号等于发新版本，需你确认用哪个号段，避免和你本地分支冲突。
