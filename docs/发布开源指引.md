# 把本项目发布到 GitHub（三种方式）

> 目标：让 `NJMU-Helper` 以 **FengHDSL/XJAU-Helper 的 Fork** 形式出现在你的 GitHub 账号下，并保留上游提交历史。

## 前置

- 一个 GitHub 账号（免费）
- 本机已安装 Git，或直接使用浏览器

---

## 方式一：网页 Fork + 上传（零命令行，最稳）

### 1. Fork 上游

打开 https://github.com/FengHDSL/XJAU-Helper ，点击右上角 **Fork** → **Create fork**。
得到的仓库地址形如 `https://github.com/你的用户名/XJAU-Helper`。

### 2. 改名为 NJMU-Helper（可选但推荐）

进入 Fork 后的仓库 → **Settings** → **Rename** → 填 `NJMU-Helper` → 确认。
GitHub 会自动把旧的 Fork 网络关系保留在页面上（显示 "forked from FengHDSL/XJAU-Helper"）。

### 3. 用本项目覆盖文件

1. 在仓库首页点 **Add file → Upload files**。
2. 把本项目根目录下的 `AppScope/`、`entry/`、`config/`、`hvigor/`、`build-profile.json5`、`oh-package.json5` 等全部拖进去。
3. 同名文件会自动覆盖，提交信息填 `feat: 适配南京医科大学教务环境`。
4. **注意**：`entry/build/`、`oh_modules/`、`local.properties`、签名文件不要上传（`.gitignore` 已列出）。

### 4. 确认仓库状态

- 仓库首页顶部应显示 `forked from FengHDSL/XJAU-Helper`
- `LICENSE` 中保留上游版权行
- `NOTICE.md` 说明衍生关系与改动清单

---

## 方式二：命令行（推荐，一次到位）

```bash
# 1. 在自己的账号下 Fork（也可在网页点 Fork）
gh repo fork FengHDSL/XJAU-Helper --clone=false

# 2. 克隆你的 Fork
git clone https://github.com/你的用户名/XJAU-Helper.git NJMU-Helper
cd NJMU-Helper

# 3. 用本项目文件覆盖工作区（保留 .git，历史不丢）
rsync -a --delete --exclude .git /path/to/NJMU-Helper/ ./

# 4. 提交并推送
git add -A
git commit -m "feat: 南医大适配版 v1.9.8（登录/课表/成绩/学业/导出）"
git push origin main
```

如需把仓库改名为 `NJMU-Helper`：`gh repo rename NJMU-Helper`。

## 方式三：GitHub REST API（无 Git 环境）

适用于只有浏览器或受限终端的环境。需要一枚 **Personal Access Token**（classic，勾选 `repo` 权限）：

1. 创建 Fork
   ```bash
   curl -X POST -H "Authorization: Bearer $TOKEN" \
        -H "Accept: application/vnd.github+json" \
        https://api.github.com/repos/FengHDSL/XJAU-Helper/forks
   ```
2. 用 Git Data API 逐层创建 `blob → tree → commit → 更新 ref`，把本项目文件写入你的 Fork。
   （`base_tree` 传上游最新 commit 的 tree，未覆盖的文件会保留。）
3. 更新仓库描述与主页：
   ```bash
   curl -X PATCH -H "Authorization: Bearer $TOKEN" \
        -H "Accept: application/vnd.github+json" \
        -d '{"description":"南医助手 · 南京医科大学教务信息鸿蒙原生客户端","homepage":"https://你的站点地址"}' \
        https://api.github.com/repos/你的用户名/NJMU-Helper
   ```

> Token 只在本机使用，不要写进任何文件或提交记录。用完后请在 GitHub 设置中删除。

## 发布后建议做三件事

1. **开启 Issues**：Settings → General → Features → Issues。
2. **添加 Topics**：`harmonyos`、`arkts`、`njmu`、`campus`、`timetable`，方便被搜索到。
3. **发布 Release**：Releases → Draft a new release，Tag 填 `v1.9.8`，附上 `.hap` 安装包（或只放下载页链接），正文直接粘贴 `CHANGELOG.md` 对应段落。
